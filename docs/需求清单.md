# 多租户知识库中台 — 需求清单

> 本文档定义多租户知识库中台的功能与非功能需求,作为开发、验收与迭代的依据。
> 技术栈基线:Milvus × Neo4j × LangGraph × Celery × PostgresSaver。
> 编制日期:2026-11-05

## 0. 范围、角色与系统边界

| 项 | 内容 |
| --- | --- |
| 系统形态 | 后端服务 + 异步任务 + 关系库 + 缓存 + 对象存储 + **双端前端** 的全栈生产化底座 |
| 管理端 | 知识库建模、文档入库与重索引、租户与权限、评估集与评估运行、Trace 查询 |
| 问答端 | 提问 → 检索 → 人机确认 → 答案与引用、评分与纠错反馈 |
| 角色 | 「三角色权限体系」的具体角色名与权限边界尚未定义 → 见 Q-1 |
| 中间件 | Postgres(业务库 + LangGraph 检查点)、Redis(缓存 + Celery broker)、MinIO(原图/解析产物)、Milvus、Neo4j |

## 1. 数据接入与离线索引

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-101 | 多格式文档解析(PDF / Word / Markdown / Excel 等) | 每种格式有样例语料入库成功,解析产物(正文、标题树、表格、图片)可查 |
| FR-102 | 标题感知的结构化切片,切片可追溯到所属章节 | 切片携带章节层级与文档偏移;同一文档重复解析得到同一批切片 |
| FR-103 | **切片幂等**:重跑不产生重复切片 | 对同一文档连续重索引 N 次,切片总数与主键集合不变 |
| FR-104 | 整页转图 + 视觉描述回填,图片内容进入切片正文并参与检索 | 图内文字/图表结论可被检索命中;答案引用可回传原图 URL |
| FR-105 | PDF 内嵌图与扫描页分别处理(内嵌图直接抽取,扫描页先转图) | 两类页面各有一条端到端用例 |
| FR-106 | 索引以 Celery 异步任务承载,带完整状态机与进度反馈 | 队列中可见 排队/进行/成功/失败/重试 状态;前端可轮询或订阅进度 |
| FR-107 | 幂等重索引 + 失败可重跑,大规模入库不丢不重 | 中途 kill worker 后重启,任务能从状态机恢复并收敛到正确结果 |
| FR-108 | 稠密向量 + 稀疏向量双路写入 Milvus,中文分词显式配置 | Collection 字段与稀疏索引类型符合 Milvus 硬约束;中文分词生效可用单字/词组用例证明 |

## 2. 检索(三路混合 + 双库融合)

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-201 | 第 1 路:正文 BM25 稀疏检索 | 单独关闭其他两路时,精确关键词用例仍能召回 |
| FR-202 | 第 2 路:章节标题 BM25 稀疏检索(独立一路) | 「按章节名找整章」类查询在仅开此路时能召回 |
| FR-203 | 第 3 路:语义向量检索 | 同义改写类查询能召回 |
| FR-204 | **RRF 融合** 排序三路结果 | 三路名次不一致时融合结果符合 RRF 定义;任一路为空不报错 |
| FR-205 | 每一路检索**独立可开关、独立可验证** | 提供逐路命中率/召回指标面板;禁止「某路静默失效被其他路掩盖」——任一路指标归零必须告警 |
| FR-206 | 图谱路五步检索:实体抽取 → 实体链接 → 受控跳数邻域扩展 → 子图线性化 → 回落原文切片 | 五步各自可观测、可断点查看中间结果 |
| FR-207 | 实体链接两级兜底:严格匹配 + 字符匹配 | 别名/错字实体在严格匹配失败时能被字符匹配接住 |
| FR-208 | 邻域扩展跳数受控(可配置上限,默认小跳数) | 超跳数请求被拒绝或截断,不产生全图扫描 |
| FR-209 | 图谱路**不直接当答案依据**,统一回落为原文切片后与向量路按同一契约合并 | 图谱路输出的每条结果都带原文 chunk 指针,无裸实体关系作为答案 |
| FR-210 | 两路结果合并、去重、统一精排(去重基于稳定主键) | 同一 chunk 被两路同时命中只出现一次 |
| FR-211 | 上下文截断按相关性优先级排序,而非按召回顺序 | 低分结果先被丢弃,高分结果不被截掉 |
| FR-212 | 无向遍历必须保留方向信息 | 线性化输出中每条关系仍标明原始方向,不因无向查询丢失 A→B 语义 |

## 3. 知识图谱建模与写入

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-301 | 实体类型与关系类型**双白名单**约束抽取 | 白名单外的抽取结果被丢弃并计入统计 |
| FR-302 | 抽取层与写入层**各设一道校验**(两道不可合并) | 绕过抽取层直接调写入接口,非法三元组仍被拦住 |
| FR-303 | Schema 约束的大模型三元组抽取(结构化输出) | 抽取结果通过 JSON Schema 校验;模型侧约束参数生效 |
| FR-304 | 实体规范化 + 稳定主键,以**复合唯一约束**承载租户隔离与幂等写入 | 同实体不同写法归一;重复写入不产生重复节点 |
| FR-305 | 全量合并的幂等写入模式 + 实体到 chunk 的桥接关系 | 每条关系必须携带原文依据与来源切片(可审计、可回溯) |
| FR-306 | 图查询语言两类硬约束的安全绕法:关系类型不可参数化、可变长度路径不可参数化 | 参数一律走白名单校验,查询构造处无字符串拼接入口 |
| FR-307 | 独立关系类型 vs 统一关系类型的取舍需在设计文档中固化 | 有明确的取舍记录,不是临场决定 |

## 4. 问答编排与人机协同

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-401 | LangGraph 状态图:意图路由 → 查询改写 → 用户确认中断 → 双路检索 → 去重精排 → 融合精排 → 相关性评估 → 生成引用 | 状态图可视化;每个节点可单测 |
| FR-402 | `interrupt()` 实现**问题级**人工确认(改写候选由用户选择) | 中断点用户可选择/编辑候选改写并继续 |
| FR-403 | PostgresSaver 检查点持久化,服务重启后中断仍可恢复 | 停在等待确认时重启服务,同一会话仍能续跑 |
| FR-404 | 五层幻觉防御,顺序执行且逐层可观测 | ① 意图路由过滤 ② 相关性评估打分 ③ 缺失信息定向重试 ④ 证据不足明确拒答 ⑤ 引用编号程序侧硬校验 |
| FR-405 | 定向纠错:**基于缺失信息改写重试**,不是随机重跑 | 重试请求中能看到本轮缺失项;同一问题不会无差别重复 |
| FR-406 | 拒答是显式终态,答案与「证据不足」在数据层可区分 | 拒答样本不进入正常答案统计口径 |
| FR-407 | 结构化输出落地四类场景:意图路由、查询改写、相关性评分、实体抽取 | 四类输出各有 Schema;思考模式与工具调用冲突有规避方案 |
| FR-408 | 答案带引用编号,引用编号由程序侧硬校验(非模型自证) | 模型输出越界/不存在的编号时,服务端拦截并纠正或拒答 |

## 5. 多租户与权限

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-501 | 防线①存储层按租户物理隔离(Milvus 分区/Collection、Neo4j 租户维度、Postgres 行级) | 无租户前缀/标识的读写路径不存在 |
| FR-502 | 防线②身份层从令牌解析租户上下文 | 上下文只能来源于已验证令牌,不接受请求体自报租户 |
| FR-503 | 防线③查询层由服务端强制注入过滤条件 | 客户端传入的过滤参数无法覆盖服务端注入项 |
| FR-504 | 防线④验收层以**真实数据**断言跨租户零泄露 | 越权用例必须拿真实多租户数据跑通,**不接受「只看函数签名」的验证** |
| FR-505 | 函数签名层面杜绝越权来源(租户上下文不由调用方传参) | 静态检查或封装约束使「传入他租户 ID」在类型层不可表达 |
| FR-506 | 三角色权限体系 | 角色定义待确认(Q-1),权限矩阵需评审后落文档 |
| FR-507 | 支撑多部门、多客户共用一套平台 | 至少 3 个租户并存的端到端演示数据 |

## 6. 评估与反馈闭环

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-601 | 在线评估:每次问答自动执行 格式检查 / 引用检查 / 安全检查 / 系统指标 | 三项检查有明确规则与失败样本可查 |
| FR-602 | 忠实性与相关性按**可配置抽样率**执行 | 配置 0%~100% 抽样率均生效,不为全量成本所困 |
| FR-603 | 离线评估四层指标:检索层 / 答案层 / Agent 层 / 系统层 | 每项指标有**明确计算口径**文档,不允许多义 |
| FR-604 | 分组切片统计 | 能定位「哪一类问题变差了」,而非只有总分 |
| FR-605 | 多组配置基线回归对比 | 单点技术改动的收益可量化(对照组 + 实验组 + 差值) |
| FR-606 | 评估集管理:从反馈池导入、版本化冻结 | 已冻结版本内容不可原地变更,可复现历史评估 |
| FR-607 | 评估运行器:可中断、可看进度 | 长跑评估可中途停止并续跑,不会因中断丢已完成结果 |
| FR-608 | 多组对照、回退样本明细、CSV 导出 | 任一次评估能导出「变差的样本清单」供逐条人工看 |
| FR-609 | 反馈回流:用户评分 + 用户提交的正确答案自动进反馈池,评估集从中导入 | 形成 使用 → 反馈 → 评估 → 优化 闭环,一条链路可追 |

## 7. 可观测、成本与运营

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-701 | 全链路 Trace 落库,覆盖:路由结果、改写候选与用户选择、两路检索候选与分数、精排前后顺序、相关性评分 | Trace 可还原一次问答的完整决策链 |
| FR-702 | 分阶段耗时统计 | 任一次请求能看出瓶颈在检索/精排/生成哪一段 |
| FR-703 | Token 与成本统计 | 按阶段与按模型可汇总 |
| FR-704 | 按租户聚合观测 | 能出单租户的量、成本、质量视图 |

## 8. 非功能需求

| ID | 需求 |
| --- | --- |
| NFR-1 | **可降级**:图谱、精排、交叉验证全链路可开关;区分「增益」与「必需」,任一非核心环节故障时主流程仍可用 |
| NFR-2 | **幂等**:切片、图谱写入、Celery 任务三处均须幂等 |
| NFR-3 | **可恢复**:中断状态、异步任务状态机在重启后均可续 |
| NFR-4 | **注入防护**:图查询参数化受限处一律白名单校验 |
| NFR-5 | **并发安全**:识别并规避「锁跨外部 I/O 持有」类陷阱 |
| NFR-6 | **租户隔离是第一优先**:四道防线缺任一道即视为未交付 |
| NFR-7 | **成本可控**:线上持续观测 token/成本,并支持抽样降低评估开销 |
